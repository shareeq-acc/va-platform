Component Reference

FastAPI core
Ingests Vapi webhook events (call-start, tool-calls, transcript, call-end). Validates schemas via Pydantic, writes idempotent call records to Postgres using a unique constraint on (call_id, event_type), invokes Gemini for summaries, and returns tool results synchronously.
Vapi Platform external
Cloud voice AI service. Manages phone number +14787584217 and AI assistant "Sarah". Posts all call lifecycle events to the webhook URL over HTTPS and provides an outbound calling API for the arq worker callback path.
Caddy proxy
Reverse proxy with automatic TLS via Let's Encrypt. Terminates HTTPS on :443 and forwards to FastAPI on :8000. In local dev mode, proxies to host.docker.internal:8000 so the server can run outside Docker.
PostgreSQL data
Stores Call and CallEvent records. Unique constraint on (call_id, event_type) ensures webhook retries are idempotent — duplicate events are detected and silently dropped without returning 5xx to Vapi.
Redis + arq Worker queue
When the sync handler fails (DB down or Gemini error), a job is enqueued to Redis. The arq worker polls /healthz every 5 seconds; on recovery it places an outbound Vapi call back to the patient's number using failed_interaction_callback.
Google Gemini AI llm
Called from the tool-calls handler to summarise patient intent (name, DOB, reason) into a concise clinical note before storing in Postgres. Falls back gracefully to a template string if the Gemini API is unavailable.
Prometheus observability
Scrapes /metrics from FastAPI every 5s (HTTP request counts, latency histograms p50/p95/p99, 5xx rate via prometheus-fastapi-instrumentator) and redis-exporter (arq queue depth). Fires alerts on thresholds defined in alert.rules.yml.
Grafana observability
Visualises Prometheus data. Pre-provisioned datasource and dashboards under grafana/provisioning/. Shows request rate, latency percentiles, error rate, and Redis queue depth panels.
Monitor UI internal
Custom HTML dashboard at /monitor served by FastAPI itself. Polls /api/monitor/stats every 5s for live call counts, event log with per-event latency, service health indicators, and Grafana credentials.
GitHub Actions ci/cd
On push to main: (1) run Pytest in ephemeral docker-compose, (2) build Docker image and push to GHCR tagged with Git SHA, (3) auto-deploy to Staging via SSH, (4) deploy to Production behind a manual approval gate.
Terraform infrastructure
Provisions the Staging VPS on Contabo and manages DNS via Namecheap. Configuration in /infra. Production was manually provisioned and is managed deploy-only through GitHub Actions SSH.
Cloudflare R2 reliability
scripts/backup.sh runs pg_dump, gzip-compresses, and pushes to a Cloudflare R2 bucket using the AWS CLI with --endpoint-url https://<ACCOUNT_ID>.r2.cloudflarestorage.com. R2 is fully S3-compatible — no region needed (auto). scripts/restore.sh supports restore from local path or s3:// R2 URI.
